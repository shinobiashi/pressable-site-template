## 指摘
### [R1-1][High][.claude/skills/rename-site/scripts/rename.py:228-236]
置換が境界なしの部分一致で、変えない側のスラッグを保護していない。README・SKILL.md が勧める「テーマ `sample-store`・プラグイン `sample-store-functions`」の組み合わせでテーマだけを変えると、プラグイン側の識別子（`.gitignore` / `.deployignore` の許可リスト、Text Domain、定数）まで `acme-theme-functions` に書き換わる。プラグインがデプロイ対象から外れ、新規ファイルが Git に無視され、CI の working-directory も存在しないパスになる。それでも自動チェックは「問題はありません」と出していた（scratch clone で再現）。
**修正方針:** 変えない側のスラッグも「自分 → 自分」として置換表に入れて最長一致で守り、スラッグの直前が英数字・`_`・`-` のときは置換しない境界を付ける。

### [R1-2][High][.claude/skills/rename-site/scripts/rename.py:229-234]
ハイフンの無いスラッグ（`shop` など）は、スラッグの形と PHP 接頭辞の形が同じ文字列になり、置換表で前者が後者に上書きされる。その結果、Text Domain・`@package`・パターンのスラッグが `acme_theme` のようにアンダースコアの形になる（R1-4 のテストで検出）。スラッグのバリデーションはハイフン無しを警告で許しているため、通常の入力で起きる。
**修正方針:** ハイフンの無いスラッグは、直後が `_` なら PHP 接頭辞、そうでなければスラッグとして置き換える。

### [R1-3][Medium][wp-content/mu-plugins/local-mail-guard.php:15-28、bin/studio-prepare.sh:57]
`pre_wp_mail` は WordPress 本体の `wp_mail()` の中でしか呼ばれないため、`wp_mail()` を自前で定義する SMTP / API 系のプラグインが本番にあると、ローカルからメールが送られる。prepare の `has_filter( "pre_wp_mail" )` はフックの登録しか見ないので、その状態でも問題なしと判定する（Studio で、`wp_mail()` を定義するダミープラグインを使って送信されることを実測）。
**修正方針:** local のときは mu-plugin で `wp_mail()` 自体を定義し（mu-plugin は通常のプラグインより先に読まれる）、prepare では実際に使われる `wp_mail()` の定義ファイルを `ReflectionFunction` で確認する。

### [R1-4][Medium][.claude/skills/rename-site/scripts/]
rename.py に自動テストが無い。全体・一部・再実行・新スラッグが旧スラッグを含む場合などの分岐が多く、R1-1 もテストがあれば検出できた。
**修正方針:** 一時ディレクトリの Git リポジトリにコピーして各シナリオを実行する `test_rename.py` を追加し、CI で実行する。
